# Tern Connections in oh-my-pig

Inventory of every Tern-specific behaviour in omp at release tag `v19.1.1` (`31ffee513f`) and its state in `oh-my-pig`.
Every connection ported here checks for Tern the way omp does and falls back to omp's non-Tern behaviour in other terminals.

| Connection | What omp does in Tern | What omp does in other terminals | Upstream file (`v19.1.1`) | State here |
|---|---|---|---|---|
| **Terminal identity & capability detection** (`TERM_PROGRAM=tern`, `KITTY_WINDOW_ID`, `isTernPane`) | `detectTerminalId` recognizes `TERM_PROGRAM=tern` → `"tern"` (Kitty graphics + Unicode placeholders, trueColor, OSC 8 hyperlinks, OSC 99 notifications). Because Tern panes may also export `KITTY_WINDOW_ID`, Tern-specific checks use `isTernPane` (`TERM_PROGRAM=tern`) or `TERN_PANE_SOCKET`+`TERN_PANE` directly. | Detects Kitty, Ghostty, WezTerm, iTerm2, VSCode, Alacritty, Warp, Orca, Otty, Rio, Monstar, Rex, or falls back to `trueColor`/`base`. | `packages/tui/src/terminal-capabilities.ts`, `packages/tui/src/terminal.ts:78-80` | **Ported (`IsTernProgram`) + library helpers** (`internal/tern/detect.go`: `IsTernProgram` is used by `TitleController`; `DetectTerminalID`, `NotifyProtocolFor`, `HasBlobDir` are exported library helpers). |
| **Tern pane socket discovery** (`TERN_PANE_SOCKET`, `TERN_PANE`) | Resolves daemon Unix socket path and numeric pane block ID for browser PiPs and user pages. | Returns `null`; disables Tern daemon features and falls back to non-Tern paths. | `packages/coding-agent/src/tools/browser/tern/kind.ts` | **Ported** (`internal/ternwire/kind.go`, re-exported via `internal/tern/detect.go`: `Pane`, `PaneFromEnv`). |
| **Terminal owner claim** (`PI_TERMINAL_OWNER_PID`) | Interactive TUI sets `PI_TERMINAL_OWNER_PID=<pid>` at startup so child processes (`bash`, eval kernels, services) inherit it and know the Tern pane belongs to the parent session rather than opening browser tabs in it. | Same env claim in cmux/other interactive terminals. | `packages/coding-agent/src/main.ts:1983-1985`, `packages/coding-agent/src/tools/browser/terminal-owner.ts:10-21` | **Ported** (`internal/tern/register.go` sets `PI_TERMINAL_OWNER_PID` on TUI `session_start`; `internal/browser/resolve.go` reads `OwnsTerminal`). |
| **Session terminal title** (OSC 0) | While a native TSP surface is live, emits the plain session name (`omp` before named) plus optional ` · #<PR>`, with no `π` brand or spinner, because Tern draws run state itself. | Emits `π > label` (idle), animated `π ⠋ label` (working; static `π : label` under Linux WSL or `spinnerInterval=0`), `π ! label` (attention, held across `agent_end` while a dialog is open), or `π: label` when `tui.titleState=false`. | `packages/coding-agent/src/utils/title-generator.ts`, `packages/coding-agent/src/utils/run-status.ts:74-76,154-165` | **Ported (with SDK caveats)** (`internal/tern/title.go`: `TitleController`, `BuildNativeTitle`, `BuildTitleWithState`, wired to `ctx.SetTitle` in TUI mode only; reads `tui.titleState`, `tui.titleSpinner`, `tui.spinnerInterval` via `tern.Setting`). Visible caveats: (1) PiG's host writes `pig - <dir>` after `session_start` handlers finish (and on rename) with no extension title-ownership API, so **until the first turn or a rename the terminal title is PiG's `pig - <dir>`** in every terminal (and after a rename the winner depends on ordering); (2) SDK cannot report whether a native TSP surface is live vs classic fallback, so native-vs-classic switches on `TERM_PROGRAM=tern`. |
| **Card-form session titles** (`<icon> <CODE>: <title>`) | Formats/parses `<icon> <CODE>: <title>` (1–8 non-ASCII runes + 1–6 ASCII uppercase/digit code) that Tern indexes parked panes by; carries the card across title regenerations (`keepTitleCard`). | Same title string appears in terminal title, `/resume` picker, and listings; degrades to plain title when `title.icons=boring` or icon/code is absent. | `packages/coding-agent/src/utils/title-card.ts`, `packages/coding-agent/src/utils/title-settings.ts`, `packages/coding-agent/src/tiny/text.ts` | **Ported (library helpers)** (`internal/tern/title_card.go`: `FormatCardTitle`, `SplitCardTitle`, `KeepTitleCard`, `ParseCardTitleReply`, `ParseCardReply`, `IsCardIcon`). Not wired to automatic LLM title generation (which is not ported); Nerd Fonts catalog lookup is accepted via an injectable resolver and degrades to emoji when nil. |
| **Session restore user vars** (`omp_restore`, `omp_session_file` via OSC 1337 `SetUserVar`) | In `TERM_PROGRAM=tern`, emits `ESC]1337;SetUserVar=omp_restore=MQ==BEL` and `ESC]1337;SetUserVar=omp_session_file=<base64 abs path>BEL` (or empty to clear on clean exit) so Tern restores the session after a crash/restart: Tern types `omp --restore\|--resume <file>` at a shell prompt or runs an agent pane's own command with the flag (a Tern plugin's `reopen` hook can rewrite it). | Writes nothing. | `packages/coding-agent/src/utils/title-generator.ts:777-835,1164-1166` | **Not ported (on purpose + SDK gap)**: Tern would type `omp --restore\|--resume <file>` in a shell pane (handing a PiG session file to `omp`), and in an agent pane PiG has no `--restore` flag and its `--resume` takes no path. PiG's extension SDK also has no raw OSC 1337 write call. Residual hazard: a stale `omp_session_file` left by an earlier crashed `omp` cannot be cleared by this Binary. (`pig-tern/frontend/session_file.go` publishes the file on a hidden `pig.session` TSP node for plugins, which Tern core does not read for restore.) |
| **Working directory report** (OSC 7 `file://host/path`) | In `TERM_PROGRAM=tern`, writes OSC 7 when cwd changes (in any Tern pane) so Tern shows the directory in the composer bar and opens splits/links there. | Writes nothing (shell reports OSC 7 at its prompt). | `packages/coding-agent/src/utils/title-generator.ts:830-835` | **Frontend lane** (`piglets/pig-tern/frontend/cwd.go` writes OSC 7 while `pig-tern`'s native surface is live; not emitted in classic/non-TSP Tern panes). |
| **Terminal progress** (OSC 9;4;3 active / OSC 9;4;0 clear) | In `TERM_PROGRAM=tern`, always emits OSC 9;4 in any Tern pane regardless of `terminal.showProgress`, because Tern reads it as the pane's busy state (tab live dot, `cx.agents`). | Emits OSC 9;4 only when `terminal.showProgress` (`terminal.showTerminalProgress` in PiG) is `true`; Ghostty/Monstar get a keepalive timer. | `packages/coding-agent/src/modes/controllers/event-controller.ts:1214-1230`, `packages/tui/src/terminal.ts:47-48,3018-3035` | **Frontend lane + PiG host (SDK gap for non-TSP Tern panes)**: `piglets/pig-tern/frontend/progress.go` emits OSC 9;4;3 (with 1s keepalive) and OSC 9;4;0 while `pig-tern`'s native surface is live; PiG's host emits OSC 9;4 when `terminal.showTerminalProgress` is enabled. PiG's extension SDK has no `SetProgress(bool)` call, so `internal/tern` cannot force OSC 9;4 in a classic (non-TSP) Tern pane. |
| **Completion, error & attention notifications** (OSC 99 / OSC 9 / BEL) | `TERMINAL.sendNotification` sends OSC 99 (`\x1b]99;…\x1b\\`, structured after `p=?` probe) in Tern/Kitty/Otty, OSC 9 (`\x1b]9;…\x1b\\`) in Ghostty/WezTerm/iTerm2/Warp/Monstar, or BEL (`\x07`) + Linux `libnotify` fallback elsewhere; `completion.notify` defaults `"on"`, `error.notify` defaults `"off"` (and skips mid-retry), `ask.notify` defaults `"on"` (once per `ask` call), `pty.notify` defaults `"on"`; suppressed by `PI_NOTIFICATIONS=off\|0\|false` and Warp OSC 777. | Same protocol selection by `TERMINAL.notifyProtocol`; BEL + `libnotify` fallback on generic terminals. | `packages/tui/src/terminal-capabilities.ts:161-199,1437-1603`, `packages/coding-agent/src/modes/controllers/event-controller.ts:2972-3033`, `packages/coding-agent/src/modes/settings.ts:1404-1428,1460-1484`, `packages/coding-agent/src/tools/ask.ts:448-459`, `packages/coding-agent/src/tools/bash-interactive.ts:115` | **Ported (degraded via SDK)**: `internal/tern/notify.go` handles `agent_end` (completion on, error off by default, aborted skipped) and `tool_execution_start` for `ask` (once per call), in TUI mode only, honouring `PI_NOTIFICATIONS`, and rings `ctx.Bell()`. SDK gap: PiG's SDK has `ctx.Bell()` (audible/visual bell) and in-TUI `ctx.Notify()` but no raw OSC 99 / OSC 9 emitter, so BEL fires where omp sends a silent OSC 9/99 toast. In Tern, PiG's OSC 7501 program status (`pig-tern/frontend/program_status.go`) also drives Tern's native notifications and pane badges. |
| **Program status** (OSC 7501) | Probes terminal with `\x1b]7501;?\x1b\\\x1b[c`; when confirmed (Tern, Rex), reports `working`, `blocked` (with question/permission msg), `done`, `error`, `clear`. | No-op when terminal does not confirm OSC 7501. | `packages/coding-agent/src/utils/run-status.ts`, `packages/tui/src/terminal.ts:1263` | **Frontend lane / PiG host** (already implemented in PiG host + `piglets/pig-tern/frontend/program_status.go`). |

| **`/fork` into a Tern split pane** (`wire.ts` `fork` op) | On bare `/fork` in a Tern pane (`TERN_PANE_SOCKET`+`TERN_PANE`, persisted session), flushes to disk and sends `{"fork":{"block":P}}` over the Tern daemon socket (10s timeout), leaving this session untouched (even mid-turn).
