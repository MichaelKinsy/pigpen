## Architecture (Dual Surface via `surface.Native()`)

- `register.go` resolves tools by name through `e.ToolRenderer(...)` using `sdk.ToolRenderShellSelf` and dispatches per call/result to:
  - **Terminal builders (`term_*.go`)** when `!surface.Native()` (or when no native builder exists): ports of omp's `renderCall` / `renderResult`. Every emitted row is split on CR/LF and measured, wrapped, or truncated using PiG SDK's `extensions/sdk/tui` (`VisibleWidth`, `WrapTextWithAnsi`, `TruncateToWidth`), never a custom width table. Zero `omp.*` node IDs. Every view is strictly bounded well below PiG's 4096-node limit.
  - **Native builders (`native_*.go`)** when `surface.Native()`: ports of omp's `describeCall` / `describeResult` carrying raw payloads (no frame chrome, gutters, or ANSI clipping) tagged with `omp.*` role IDs as specified in `VIEW-IDS.md`.
- Per-session status-line state, cached footer snapshot, and per-session card `Invalidate` closures live in ONE package-level table (`chromeSessions`) keyed strictly by session ID (never a shared default) and are released through `lifecycle.OnEnd("ansi", ...)`. A single `surface.OnChange` subscription updates/invalidates only live sessions, clearing terminal header/footer on terminal→native transitions.
- Status-line repaints coalesce via `SetFooterRenderer` on model, thinking, session-info, turn-end, and agent start/end events while keeping zero host IPC inside the renderer callback.
- Working messages derive exclusively from `intent.WorkingLabelFromEvent(ctx, data)` (`internal/intent`, applying omp's label-then-normalize order).
