# Upstream Reference: `internal/lsp`

Port of omp's `lsp` tool and post-write LSP diagnostics (`https://github.com/can1357/oh-my-pi`, MIT, release tag `v19.1.1`, commit `31ffee513f`).

## Model-Facing Surface at `v19.1.1`

- Tool name: `lsp` (`label: "LSP"`).
- `loadMode` at tag `v19.1.1`: **`"discoverable"`** (`packages/coding-agent/src/lsp/tool.ts:328`), default-on (`lsp.enabled: true`, `BUILTIN_TOOL_HELP.lsp.defaultState = "on"`). Registered with `Exposure: sdk.ToolExposureCodemode`, `DefaultActive: new(false)`, and `toolcmd.Mountable("lsp", Enabled)` so `internal/toolcmd` mounts it as a `bash` command when `tools.commands` is on (executing through `Context.ExecuteTool` with host validation/hooks/gates) and activates it top-level when the command transport is off.
- `summary` / `PromptSnippet`: `"Query LSP (language server) for diagnostics, hover info, and references"`.
- Description: embedded verbatim from `packages/coding-agent/src/prompts/tools/lsp.md` (`lsp.md`), rendered with omp's default timeout settings (`defaultTimeoutSec=20`, `defaultWaitSec=10`, `maxTimeoutSec=300`).
- Schema: exact match of `arkToWireSchema(lspSchema)` (`packages/coding-agent/src/lsp/types.ts:9-23`) built with `sdk.Type.Object` + `sdk.NewOrderedObject` to preserve exact property order (`action`, `file`, `line`, `symbol`, `query`, `new_name`, `apply`, `timeout`, `payload`), enum values, bounds (`minimum: 5`, `maximum: 300`), description, `required: ["action"]`, and `additionalProperties: false`.
- Result `Details`: `LspToolDetails` (`serverName`, `action`, `success`, `request`) matching `packages/tui/src/tools/lsp.ts`.

## Changed on Purpose (PiG Host Integration)

- **Project Trust Gating** (`config.go`, `client.go`, `tool.go`, `writethrough.go`): omp has no project-trust concept, whereas PiG disables project-scoped settings and hooks in untrusted repositories (`sdk.Context.IsProjectTrusted()`). In this port, server commands declared in project-directory config files (`<cwd>/lsp.*`, `<cwd>/.omp|.claude|.codex|.gemini/lsp.*`) and project-local binaries (`node_modules/.bin`, `.venv`, `venv`, `.env`, `vendor/bundle/bin`, `bin`) are loaded ONLY when `ctx.IsProjectTrusted()` returns `(true, nil)` — including in background paths such as the idle checker and eager warmup. In an untrusted project (or when the trust query fails), only user-level configuration and binaries found on `PATH` are used, and a one-time note is appended to the first `lsp` result in that session when project config or local bins were skipped. Known exposure (matching omp): a trusted `PATH` language server started in an untrusted workspace still runs with that directory as its workspace, so servers that execute workspace code themselves (for example `rust-analyzer` build scripts or `tsserver` loaded from workspace `node_modules`) remain outside this gate.
- **Per-Session Lifecycle & Reference Counting** (`client.go`, `diagnostics.go`, `writethrough.go`, `register.go`): PiG creates a fresh extension instance per session while package-level state is shared across concurrent parent/child sessions, and child sessions emit no `session_shutdown` event. `Register` registers `lifecycle.OnEnd("lsp", endSession)` against the single package-level `defaultManager` and `ledgers` map: servers are reference-counted per session ID and stopped only when the last holding session leaves (under a bounded graceful shutdown budget), and only the ending session's dedupe ledger is deleted. Calls with an unresolved session ID attach any started server to an ephemeral request-scoped owner that releases on return, skip background warmup, and skip diagnostics deduplication rather than sharing a `_default` bucket.
- **Mutation Gate, File Mutation Queue & Hashline Snapshot Refresh** (`edits.go`, `client.go`, `tool.go`, `writethrough.go`): every file-mutating LSP operation (`rename`, `rename_file`, `code_actions`, server `workspace/applyEdit`) checks `internal/gate.Check` (`OpEdit`/`OpWrite`/`OpMove`/`OpDelete`) before touching disk (server-initiated `workspace/applyEdit` uses the active tool call's live `sdk.Context` and replies `applied: false` when none is resolvable), serializes writes through PiG's host file mutation queue (in both subprocess and fused in-process deployments, running each mutation at most once), and refreshes the calling session's `internal/hashline.ForSession(ctx)` snapshot store so subsequent hashline edits see current tags.

## Settings Read

By default `readSettings` reads PiG's host settings map via `ctx.GetSettings()`. To read omp's `cfg://` store (`internal/settings`), the integrator sets `lsp.SettingsReader` to a reader backed by `internal/settings`.

| Setting | Default | Honoured |
|---|---|---|
| `lsp.enabled` | `true` | Yes (`Enabled(ctx)` predicate for hiding the tool, plus gates execution and `DiagnosticsAfterWrite`/`DiagnosticsAfterEdit`) |
| `lsp.lazy` | `true` | Yes (servers start on first use; when `false`, `session_start` warms up detected servers asynchronously) |
| `lsp.shared` | `true` | Read, not used (daemon-shared mux not ported; local per-root-and-language stdio servers are shared across sessions in-process with refcounting) |
| `lsp.formatOnWrite` | `false` | Partially: formats written file on disk through the file mutation queue and refreshes its hashline snapshot, but `DiagnosticsAfterWrite` returns only a diagnostics string so `write` does not update its reported byte count/header or `formatter` detail |
| `lsp.diagnosticsOnWrite` | `true` | Yes (controls `DiagnosticsAfterWrite`) |
| `lsp.diagnosticsOnEdit` | `false` | Yes (controls `DiagnosticsAfterEdit`) |
| `lsp.diagnosticsDeduplicate` | `true` | Yes (per-session `DiagnosticsLedger` reduces repeated diagnostics across writes; skipped when session ID is unresolved) |
| `lsp.requestTimeout` | `10` (s) | Yes (wait budget for project-aware diagnostics and post-write diagnostics; tool description timeout text is static from defaults because PiG registers tool descriptions once at `Register`) |
| `tools.maxTimeout` | `0` (unset) | Yes (caps `lsp` call and wait budgets when positive) |
| `symbolPreset` | `"unicode"` | Yes (selects `unicode` / `nerd` / `ascii` symbol-kind icons in `symbols` output via `lsp.Setting` or `lsp.SettingsReader` / host settings) |

## Exported Hooks for Integrator

- `func Register(e *sdk.Extension)`: registers the `lsp` tool (`Exposure: sdk.ToolExposureCodemode`, `DefaultActive: false`), `toolcmd.Mountable("lsp", Enabled)`, `lifecycle.OnEnd("lsp", endSession)`, `session_start` (optional eager warmup when `lsp.lazy=false`), and `session_shutdown` (calls `lifecycle.End(sessionID)`).
- `var SettingsReader func(ctx sdk.Context) (map[string]any, error)`: point at `internal/settings` so `cfg://lsp.*` values reach `internal/lsp`.
- `var Setting func(ctx sdk.Context, key string) any`: point at `settings.Any` so non-`lsp.*` settings (`symbolPreset`) reach `internal/lsp` (can also be included in `SettingsReader`).
- `func Enabled(ctx sdk.Context) bool`: predicate for hiding `lsp` from the tool list / `toolcmd` when `lsp.enabled` is `false`.
- `func DiagnosticsAfterWrite(ctx sdk.Context, path string) string`: called by `internal/files` after `write` commits; returns `\n\nLSP Diagnostics (<summary>):\n<grouped>` or `""`.
- `func DiagnosticsAfterEdit(ctx sdk.Context, path string) string`: called by `internal/files` after `edit` commits; returns `""` under default `lsp.diagnosticsOnEdit: false` while notifying active servers of file changes.
- `func ShutdownAll()`: process-exit / test teardown of all active and mid-initialize language servers.
