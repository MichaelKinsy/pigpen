## Changed on purpose (integrator decisions for PiG / omp coexistence)

- **Only this Piglet's own config files are read and written:**
  - Global: `<agentDir>/config.yml` (or an existing `config.yaml`), where `<agentDir>` is `$PIG_CODING_AGENT_DIR` if set, else `<ctx.ConfigHome()>/agent` (`~/.pig/agent`, `$PIG_HOME/agent`, `$XDG_CONFIG_HOME/pig/agent`).
  - Project: `<cwd>/.pig/config.yml` (or an existing `<cwd>/.pig/config.yaml`).
  - Real omp's project files (`.omp/settings.json`, `.omp/config.yml`, `.omp/config.yaml`) are **never** read, so a user running both `omp` and `oh-my-pig` on the same repository will not have omp's project config silently alter this Piglet.
  - PiG's own `.pig/settings.json` (and `<agentDir>/settings.json`) is **never** read because it has PiG's own schema (e.g. `"skills": [...]`, flat `"theme": "dark"`) which would collide with omp's groups.
- **Overlays use `PIG_CONFIG_FILES`**, following PiG's `PIG_*` env-var convention instead of omp's `PI_CONFIG_FILES`, so real omp overlays do not leak into this Piglet.
- **Project settings require PiG project trust:** the project file is loaded only when `ctx.IsProjectTrusted()` is true (queried once when the session state is created, refreshed on `session_start` and `before_agent_start`, never on `project_trust`, preserving session overrides) and `cwd` is not the user's home directory.
- **Safe `/save`, comment preservation, concurrency, and malformed-file handling:**
  - One shared global layer per resolved config file path (`sharedGlobalLayer`) is shared by all sessions and refreshed on save or when the file's stat signature (`dev`, `ino`, `ctime`, `mtime`, `size` on Unix; `CreationTime`, `LastWriteTime`, `size` on Windows) changes, with zero global-map clones on steady-state reads. Per-session state (overrides, warnings, `cfg://` grants, resolved trust and cwd) lives in a single `map[sessionID]*sessionState` released via `internal/lifecycle` on every `session_shutdown` (with bounded tombstones preventing late re-creation between `session_shutdown` and the next `session_start`; `session_start` clears any tombstone so `/reload` and `/resume` reuse the same session ID cleanly). Because per-session state is released on every `session_shutdown`, **session (runtime) overrides do not survive `/reload` or `/resume`** (whereas omp keeps runtime overrides across a reload). Subagents resolve parent overrides lazily by parent session ID via the `ParentSession` hook without ever holding `sessionsMu` and `Store.mu` simultaneously.
  - `/save` skips rewriting the file when the value on disk already matches. Real writes run under a per-path in-process mutex plus a permanent OS advisory lock file (`<target>.lock`, mode `0600`, opened with `O_NOFOLLOW` on Unix using `flock(LOCK_EX)` and `LockFileEx` on Windows, released by closing the handle with no PID/age guessing or file removal), clean up orphaned `.<basename>.*.tmp` regular-file siblings belonging to that target only (never touching another target's temp files in the same directory), re-read the file on disk, patch the key's line in place (or append cleanly) preserving comments, per-line EOLs (including LF, CRLF, lone CR, mixed EOLs), and missing trailing newlines for scalar values, fall back to full re-serialization only for non-scalar/flow values (warning the user in the approval prompt BEFORE approval and noting in the `cfg://` result text when comments were not preserved), re-parse to verify the output matches the intended document, preserve file permissions, follow symlinks (including dangling chains), rename atomically from `.<basename>.<random>.tmp`, and publish the updated shared global snapshot inside the file lock so concurrent readers emit `OnChange` exactly once per change.
  - A malformed global file is **never** overwritten or quarantined aside: `StoreFor` caches the session store with its `globalErr` (so session overrides persist and reads do not re-parse on every call), surfaces a warning once per session via `ctx.Notify`, refuses `/save` naming the file and parse line, emits `OnChange` when an external edit breaks the file (reverting configured values to defaults), and automatically retries loading when the file's stat signature changes.
  - A malformed project file emits a warning once per session via `ctx.Notify` and skips only that project file, keeping the user's global config intact.

## Not ported

| Feature | Why not ported |
|---|---|
| Preserving session (runtime) overrides across `/reload` or `/resume` | Per-session state is released via `lifecycle.End` on every `session_shutdown` (including `reload` and `resume`), so runtime overrides do not survive `/reload` or `/resume` (whereas omp keeps runtime overrides across a reload). |
| Live filesystem watcher + debounced reload (`fs.watch` / `CONFIG_WATCH_DEBOUNCE_MS`) and symlink-target re-watching | PiG extensions do not own background file-watcher loops; instead, `sharedGlobalLayer` stats `(dev, ino, ctime, mtime, size)` on read (one `os.Stat`, zero map clones when unchanged) to pick up external edits and cross-session saves, and `OnChange` notifies every live affected session. On Windows, `Win32FileAttributeData` provides `CreationTime`, `LastWriteTime`, and `size` without an extra `GetFileInformationByHandle` call, so Windows file-index tracking is omitted. |
| Stale-mutation conflict skipping (`pendingChangeApplies`) | Saves serialize under a per-path mutex + OS advisory lock (`flock` / `LockFileEx`) on a permanent `.lock` file and re-read disk immediately before applying the single target key (disjoint concurrent edits across goroutines and processes never overwrite each other); omp's same-key stale-write skip is not ported because saves are synchronous rather than debounced in a background queue. |
| Preserving comments when rewriting multi-line or flow-collection values | Single-line scalar updates and appends patch the original YAML text in place and preserve all comments, mixed EOLs, lone CRs, and missing final newlines; replacing multi-line arrays/records or flow collections falls back to re-serialization, warns the user in the approval prompt before approval, and notes in the `cfg://` result text that comments were not preserved. |
| Quarantining broken YAML files to `.broken-<timestamp>-<pid>-<uuid>` | Changed on purpose per integrator decision: malformed files are never moved or overwritten; a warning is surfaced via `ctx.Notify` and `/save` refuses naming the parse line. |
| Legacy SQLite `agent.db` settings migration and `~/.omp/agent/settings.json` -> `config.yml` auto-migration | Changed on purpose: PiG keeps its own `settings.json` under `~/.pig/agent/settings.json`; oh-my-pig reads/writes only its own `config.yml`. |
| Full `#migrateRawSettings` legacy rewrites (`doubleEscapeAction`, `lastChangelogVersion`, `collapseChangelog`, `inspect_image`, Kokoro voice renames, v17 nested leaf renames, etc.) | Only `queueMode` -> `steeringMode` and flat `theme` migration are ported; oh-my-pig writes fresh `config.yml` files rather than migrating pre-v18 omp installations, and `isLightTheme` luminance lookup from custom theme JSON files is approximated by theme name heuristic. |
| Third-party discovery providers (`.claude/settings.json`, `.codex`, `.gemini`, `.cursor`, `.omp/*`) | Changed on purpose per integrator decision: only this Piglet's `.pig/config.yml` / `.yaml` is read at project scope. |
| `PIG_USE_PI_DIRS` Pi-sharing directory redirect | `sdk.Context.ConfigHome()` does not read `PIG_USE_PI_DIRS` (PiG's `configroot` keeps PiG state under `PIG_HOME` / `~/.pig`); `PIG_CODING_AGENT_DIR` still overrides the agent directory. |
| `protocolDefault` soft-pinning for 41 settings in RPC/ACP modes | `internal/settings` is a shared extension package without a standalone RPC/ACP host startup hook (`main.ts:applyProtocolDefaults`); callers in RPC mode can pass `StoreOptions.Overrides` if needed. |
| Process-wide `effect(...)` / `Derived.listen(...)` reactive subscriptions and worker-thread `Settings.mirror` | Go callers read typed getters directly on each operation; PiG extensions do not use JS worker-thread mirrors. |
| Interactive `/settings` TUI overlay and `omp config` CLI subcommands | UI overlay and CLI commands belong to the modes/frontend lanes, not `internal/settings`. |
| 3-choice `"Always for this session"` selector in default `Context.Confirm` prompt | PiG's `sdk.Context.Confirm` is yes/no only; session-grant logic is implemented in `decideApproval` (keyed on `GetSessionID()`) and active whenever a custom `ApprovalHost` returns `ApprovalSession`. |
| Abort signal cancellation of a pending `cfg://` approval prompt | PiG's `sdk.Context.Confirm` / `ConfirmWithOptions` do not take a `context.Context` or `AbortSignal` parameter (only `DialogOptions.Timeout`). |
| Subagent `taskDepth > 0` detection in `CfgHandler.Write` | PiG's `sdk.Context` and `urls.Context` do not expose `taskDepth` or `settingsApproval` per call; `CfgHandler.Write` gates on `HasUI() && Mode() == "tui"` (refusing print, JSON, and RPC) and `PromptDoc` gates on `urls.SchemeHost.SettingsApproval`. |
| Full YAML 1.2 features (anchors/aliases `&`/`*`, multi-line block scalars `\|`/`>`, explicit tags `!!`, multi-line flow collections, multi-document streams `---`) | Implemented a stdlib-only YAML subset covering block/flow mappings, block/flow sequences, inline sequence mappings, quoted/plain scalars, comments, and single `---`/`...` markers — without adding third-party Go modules. Unsupported constructs fail loudly with a line number rather than silently misparsing. |
| Deep custom validators for `compaction.modelThresholds`, `task.agentCompactionThresholdOverrides`, `task.agentAccountPools`, `task.agentServiceTierOverrides`, `task.agentSoftRequestBudget`, `contextFiles.extra` | Core type/enum/items checks plus numeric/URL/path validators (`find.hitThreshold`, `session.*Cost`, `judgment.attemptTimeoutMs`, `task.workerThreads`, `tools.restrictedFolders`, `tui.spinnerInterval`, `tui.maxFps`, `providers.maxInFlightRequests`, `systemPromptTemplates`, `live.endpoint`, `spotlight.experiment.*`, `task.perCallModelAllow`) are ported and run on load and write; remaining deep nested-schema validators are omitted because they depend on omp's catalog/model-threshold subsystems not present in `internal/settings`. |
