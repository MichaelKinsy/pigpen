## Runtime & bridge architecture

- **Python kernel (`py_kernel.go`)**: Spawns `python3` (honouring `python.interpreter`, active/project venvs, `~/.omp/python-env`, and PATH) running omp's embedded `py_runner.py` and `py_prelude.py` verbatim over NDJSON stdio pipes. One persistent subprocess per `(sessionID, cwd, interpreter)` tuple; restarted on `reset: true`; interrupted with `{"type":"interrupt"}` + `SIGINT` on POSIX (on Windows, `CREATE_NEW_PROCESS_GROUP` + `GenerateConsoleCtrlEvent(CTRL_BREAK_EVENT, pid)` with `buildPythonInitScript` forwarding `SIGBREAK` to `SIGINT` via `signal.raise_signal`, escalating to process-tree kill after 5s — **not run on Windows**); unexpected mid-execution death emits `[kernel] Python kernel exited with code N` + omp's uncertainty annotation.
- **JavaScript kernel (`js_kernel.go`, `js_runner.js`, `js_rewriter.cjs`)**: Spawns `bun` when on PATH, else `node` (v22+), staging both `js_runner.js` and the generated omp rewriter bundle `js_rewriter.cjs` (`//go:embed`) into the per-uid 0700 staging dir and loading omp's `js_prelude.txt` via `indirectEval`. On POSIX, protocol NDJSON runs on dedicated extra pipe FDs (`3`/`4`), isolating fd `0` (`/dev/null`) and fd `1`/`2` (captured as cell stdout chunks) from user code and spawned children, plus a `worker_threads` parent-PID watchdog so a busy synchronous loop cannot outlive a killed host.
  - **Cell rewriter & execution**: Runs omp's unmodified `wrapCode`, `diagnoseCellSyntaxError`, `indirectEval`, and `awaitMaybePromise` bundled from `v19.1.1` (`31ffee513f`) with `@babel/parser@7.29.9` (parser options: `sourceType: "module"`, `allowAwaitOutsideFunction`, `allowReturnOutsideFunction`, `allowImportExportEverywhere`, `allowNewTargetOutsideFunction`, `allowSuperOutsideMethod`, `allowUndeclaredExports`, `errorRecovery`, `plugins: ["typescript"]`). Static `import`, dynamic `import(...)`, top-level `await`/`return`, TypeScript syntax stripping, lexical demotion, async-cell binding globalization/assignment instrumentation, call-site wrapping, final-expression capture/suppression, and Babel `SyntaxError` code-frame diagnosis with caret alignment execute identically to omp's `runtime.ts:540-599` and `worker-core.ts:398-406`.
  - **Bun-only APIs under each runtime**:
    - Under **`bun`**: `Bun.Transpiler` and `Bun.stringWidth` are native Bun APIs, and local module imports run through omp's bundled `LocalModuleLoader` (`vm.SourceTextModule`, `.ts`/`.tsx` stripping, mtime cache invalidation, cycle handling).
    - Under **`node` (22+)**: `js_runner.js` loads `js_rewriter.cjs` via `vm.compileFunction(..., ["exports", "require", "module", "__filename", "__dirname", "Bun"])` passing a private `Bun` shim parameter — never published to `globalThis` (so `typeof Bun === "undefined"` inside cells). The shim provides `stringWidth` (using `util.stripVTControlCharacters` + `Intl.Segmenter` + Unicode East Asian Width/Emoji/zero-width rules, verified against native `Bun.stringWidth` on an 88-string table) and `Transpiler` (using `node:module`'s `stripTypeScriptTypes(code, { mode: "transform" })` with an async-function fallback for top-level `return` cells, or leaving source unstripped on older Node builds lacking `stripTypeScriptTypes`, in which case TypeScript cells fail with a normal JS `SyntaxError`). Local module imports resolve against the active cell/cwd with extension probing, track the transitive local dependency graph via `collectModuleSourceSpecifiers`, bump every importer transitively (cycle-safe) on any dependency mtime change, and rewrite transitive ESM dependency URLs via `module.registerHooks` (`?omp-v=N`).
  - When neither `bun` nor `node` 22+ is on PATH, JS cells return an unavailability error while Python cells continue working.
- **Bridge (`bridge.go`)**: A process-local `127.0.0.1:0` loopback HTTP server with per-process Bearer token authentication (`POST /v1/tool`). Both Python and JS kernels talk to this bridge for:
  - `__prelude__`: invokes registered `eval.Prelude`s via `LookupPrelude(name).Invoke` while pausing `IdleTimeout` and surfacing images.
  - `__agent__` / `__workpool__`: routes to host-only `LookupPrelude("agent").Invoke` / `LookupPrelude("workpool").Invoke` (returning `res.Details` directly) while keeping omp's built-in `agent`/`workpool` globals in `prelude.py`/`prelude.txt`; skips installing snippets or raising reserved-global conflicts for those two preludes.
  - Session tools (`tool.<name>(args)`): dispatches via PiG SDK `sdk.Context.ExecuteTool` while pausing `IdleTimeout`. Raises exceptions in the cell when `outcome.IsError` is set without `details.isError`, and returns `{text, details, hasError: true}` when `details.isError` is set. Guards against re-entrant `tool.eval` on the same language kernel.
  - `__shell__`: runs `sh(...)` directly on the system shell without auto-backgrounding, with `WaitDelay` so detached children cannot hang `cmd.Wait`.
  - `__budget__`: resolves active turn/goal token budget via `TurnBudgetHook` (returning `{total: nil, spent: 0, hard: false}` when unset).
  - `__completion__`, `__judge__`, `__judge_batch__`: host-side one-shot completion handles (capped by shared `EvalHandleConcurrency = 32` semaphore, with structured `schema` JSON instructions/parsing and `attempts` tracking), structured `choice`/`bool`/`score` judging via `@judge` → `@smol` → active model, and concurrent host-owned `judge_batch` runs (`create`/`attach`/`status`/`drain`/`results`/`failed`/`cancel`/`close`). Cleaned up on `lifecycle.OnEnd("eval-completions", ...)`.
  - `__wait__`, `__status__`, `__cancel__`: resolves both `"agent"` handles against `internal/jobs` (`jobs.Get`, `jobs.JobDetailer` including `evalResult.data` and `ErrorText`) and `"completion"` handles against the per-session completion store.
- **Session lifecycle & plan mode**:
  - `gate.Check(ctx, gate.Request{Tool: "eval", Op: gate.OpExec, Detail: title or language})` runs before executing every cell.
  - Package-level `defaultManager` stores all kernels keyed by `sessionID`; calls without a valid session ID fail instead of sharing a fallback key.
  - `Register` installs `lifecycle.OnEnd("eval", ...)` pointing at `defaultManager.ShutdownSession(sessionID)` and `OnSessionShutdown` forwards only the ending session's ID to `lifecycle.End(id)`. Repeated `Register` calls across sessions in one process are idempotent and never disrupt other live sessions.
- **Bounded output & live updates**:
  - Kernel output is streamed into a bounded rolling tail (`boundedOutputBuffer`, capped at 2x `DefaultOutputMaxBytes` in memory, finalized on a line or UTF-8 rune boundary to <= 50 KiB) with omp's `details.meta.truncation` (`TruncationMeta`) and model-facing `[Showing lines ...]` notice.
  - Live output, status events, and timeout-clamp notices stream via throttled `sdk.Context.OnUpdate` (50ms).

## Settings

| `eval.py` (`PI_PY`) | `true` | Yes (via `Setting`) | Disables Python backend at execution and narrows tool description, `<examples>`, & schema at `session_start`. Falls back to `ctx.GetSettings()` + `PI_PY` when `Setting == nil`. |
