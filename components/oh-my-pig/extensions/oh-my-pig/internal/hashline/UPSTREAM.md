## Block-Op Resolution (`N*`) — Per-Language Coverage vs Real `omp v19.1.1`

Block operations (`PUT N*:`, `CUT N*`, `PUT >N*:`, `PUT >N* @reg`) are **strictly lexical** in this pure-Go port (no tree-sitter/cgo) and **refuse conservatively whenever unsure** so the model falls back to explicit line ranges rather than ever applying a wrong span.

Measured offline against the real `omp` 19.1.1 binary via `python3 -B internal/hashline/gen/gen_blockspans.py --sample all` (driving `piglets/oh-my-pig/proof/oracle.sh` in `omp-only` mode with 0 network) across three mutually disjoint fixture sets checked into `testdata/blockspans/` (10,568 total anchors across 387 files from omp v19.1.1 MIT and PiG/Pigpen-authored sources; zero vendored/third-party trees):
- **Sample 1** (`<lang>.json`, 2,418 anchors): curated real files + constructed Y1 / C1 / W1–W8 / N1–N5 / pass-1 adversarial fixtures.
- **Sample 2** (`sample2_<lang>.json`, 4,067 anchors): fresh discovery sample (>=440 anchors per resolvable language, SHA-256 disjoint from Sample 1).
- **Sample 3** (`sample3_<lang>.json`, 4,083 anchors): held-out validation sample (>=440 anchors per resolvable language, SHA-256 disjoint from Samples 1 & 2).
- **YAML third-party hold-out** (not checked in; evaluated read-only in a temporary scratch directory after Y1 with zero rule changes afterwards): 87 third-party files (`~/go/pkg/mod` + `~/.cargo/registry/src`), **1,666 anchors**: `677` omp-resolved, `644` equal, `33` refused-where-omp-resolves, `989` refused-both, **0 WRONG**.

`TestBlockSpansAgainstRealOmpOracle` enforces **0 WRONG spans** across all 30 checked-in fixture files on every run. Refusals store a compact `refused_kind` (`unresolved`, `single_line`, `blank`, `no_grammar`) with one verbatim omp refusal message preserved per kind in each fixture file.

## Not Ported

| Feature | Reason |
|---|---|
| Tree-sitter block resolution for unmodeled languages and non-trivial constructs (C/C++ `.c`/`.h`/`.cc`/`.cpp`/`.cxx`/`.hpp`/`.hh` removed per W8, CSS/SCSS `.css`/`.scss` removed per C1, shell `.sh`/`.bash`/`.zsh`, `.tf`/`.hcl`, `.ps1`, `.r`, `.nix`, `.graphql`, `.php`, `.kt`, `.java`, `.dart`, `.scala`, `.groovy`, `.swift`, `.cs`, `.rb`, `.lua`, `.html`/`.xml`/JSX tags, WASM-downloaded `.proto`/`.sol`/`.zig`/`.bzl`/`.star`, multi-line signatures/conditions/chains, Allman braces, `case`/`default`, Rust `where` clauses, macro bodies, and `#[...]` match arms, Markdown paragraphs/lists/HTML blocks/front-matter, YAML multi-line plain scalars/flow collections/doc markers/Go-Jinja templates, Vue/Svelte/Astro embedded blocks) | Pure-Go extension with no cgo/tree-sitter. Block ops are strictly lexical and refuse conservatively with upstream's `block_unresolved_message` / `block_single_line_message` whenever unsure so the model uses explicit ranges instead of risking a wrong span (0 WRONG spans across 10,568 checked-in oracle anchors + 1,666 YAML third-party hold-out anchors). |
| Tree-sitter `native_block_context` (`diff_string.rs:455-492`) for languages outside Python/YAML/Markdown and non-bracketed constructs | Indentation/heading boundary context IS ported for Python, YAML, and Markdown (`FindBlockContextLinesForPath`, matching omp's `mod.py` oracle reply verbatim) alongside lexical bracket context for brace languages; other non-bracketed grammars (Ruby, Lua, Bash, HTML/JSX) fall back to lexical brackets only, so edit replies omit their non-bracketed enclosing-block rows. |
| Tree-sitter syntax-probed checks in `apply.rs` (`boundary_fix_rejection`, `landing_rejection`, `trailing_comma_replacement_message`, `ambiguous_boundary_placement_message`, `edit_broke_parse_warning`, and parse-based acceptance of boundary echoes at `apply.rs:451-458`) and `session.rs` (`parse_regressed` warning, blackbox recording, auto-repair) | Require tree-sitter (`omp_ast::summary::parse_code_status` and `node_chain_at`). Because `parsesCleanly` always returns `false`, boundary echoes are refused rather than parse-accepted. `annotationEcho` uses `@`/`#[` prefix matching rather than grammar node kinds, so C# `[Attr]` and CSS `@import` behave differently. |
| Tree-sitter `enclosing_context` check in `recovery.rs` (`context_preserved`) and parse-regression refusal on shifted recovery | Require tree-sitter; text-diff line map, neighbor context validation, duplicate-line guard, and `aimed_at_authored_lines` similarity check ARE ported. |
| Non-hashline edit modes (`replace`, `patch`, `apply_patch`, `sloppy`, `magic`) and Lark custom wire grammar (`customFormat`) | Only default `hashline` mode is ported. |
| Compact edit prompt variant (`packages/coding-agent/src/edit/hashline-compact.md`) | Only default `crates/edit/prompts/hashline.md` is embedded in `internal/files/edit.md`. |
| Streaming argument delta previews (`openArgStream` / `ArgStream`) | Engine-level `PreviewPatch` and `ParsePatchStreaming` are ported, but PiG extension tool calls receive complete arguments. |
| Unique-suffix missing-path recovery (`FileCache::take_recovery_misses`) and remote SSH mirror writes (`remote-mirror.ts`) | Deferred; tag-based sandbox path recovery (`recoverTarget`) IS ported and wired with `urls.SandboxRoots(...)` in `internal/files/edit.go`. |
| LSP format-on-write and ACP bridge writethrough | Deferred; LSP diagnostics run via `SetDiagnosticsHook` and post-write `did not change on disk` verification IS ported in `internal/files/edit.go`. |
