# Port record: stretchtext

Original: **pi-stretchtext 0.1.0** by Michal Pikosz (MIT), commit `c93b06876aefdfab99171145ef1cdf695bb5ada4`, kept
unmodified in [`oracle/`](oracle) (the demo animation omitted). Its parser, growth and guide come from **cc-stretch** by
pro-vi (MIT), revision `910fb99d43bfad23d591b36aebd6c25bd0729081`. Built against the PiG Extension SDK that carries the
`tui` handle (`ctx.TUI()`) and OSC 8 link claims (`ctx.OnLinkClick`, PiG D193). Credits: [`../CREDITS.md`](../CREDITS.md).
Research and measurements: [`RESEARCH.md`](RESEARCH.md).

Kind 1: a Pi TypeScript extension. It is a whole-repository port: nothing of the original is left out except its demo
GIF.

## Differences from the original

D1 was the word segmenter of `grow.go` (the port first used a Unicode word-break approximation for Thai, Lao, Khmer and
Myanmar). It is closed: `grow.go` uses `components/pitui/wordsegmenter`, PiG's ICU 78.3 dictionary engine, and all 121
growth cases of those scripts match the original frame by frame. There is no D1 left.

- **D2. A click arrives as an OSC 8 address, not as a read of the drawn line.** The original patches
  `Markdown.prototype.handleMouse` of Pi, reads the screen row under the click and looks the link up in it. PiG has no
  patch point; its fullscreen TUI hands the address under a click to an extension that claimed the scheme
  (`ctx.OnLinkClick("stretchtext", …)`, D193) and opens nothing. The links the port draws are the original's (a
  `stretchtext:<n>` address on the short form and on `«`); `LinkTable.Resolve` takes the address where the original took
  the line. Closed-stretch screens are byte-identical in Pi and PiG (tmux scenarios below).
- **D3. The host's TUI and theme arrive with the session, not through a widget.** The original gets its `TUI` and `Theme`
  from an empty widget factory below the editor. A Go extension runs out of process and has no factory; `session_start`
  hands it the context, and `ctx.TUI()` and `ctx.UITheme()` give the same two things. Only a terminal session attaches
  (`ctx.Mode() == "tui"`); the original attached in the same sessions, since print, JSON and RPC modes never draw the
  widget.
- **D4. One lock, one redraw worker.** The original is single-threaded. Here a handler, the animation timer and the host's
  Markdown requests meet, so the store runs every change under one lock, and `invalidate()` then `requestRender()` run on
  a worker that coalesces the requests made while one is pending, as the original's `Screen` coalesces those of one tick.
  The worker is joined at `session_shutdown`.
- **D5. The letter prompt is a focused component of the SDK**, `ctx.Custom`, which the original reaches through
  `ctx.ui.custom`. Its line, its colour (`dim`) and its cut (`line.slice(0, width)` with a negative width counting from
  the end) are the original's.

## Not changed, though it looks like a defect

The original remembers every text its Markdown transformer is asked to draw that holds a stretch, and Pi asks for every
streamed prefix. A prefix that already holds a complete stretch is remembered as a reply of its own; the three latest
such texts take the letters of `alt+o`, so letters can go to stretches of a text that is no longer on screen, and a
letter typed for one opens nothing visible. The port remembers texts in the same way (`State.remember`), so it shows the
same behaviour under a host that draws every prefix. It was observed under Pi with the mock model streaming 12 characters
at a time (the first `keyboard` run: Pi lettered `s` and `d` where PiG lettered `a` and `s`). PiG's asynchronous
transform draws the latest text only, so the scenarios stream the reply as one delta and compare like with like.
Fixing it changes the original's behaviour and needs the owner's approval; it is not done.

## Evidence

Layer 1, `go test` in `extensions/stretchtext` (no network, no host):

- `diff_test.go` replays the inputs of `drive/cases.json` through the port and compares with `golden/states.json`, which
  `drive/drive.mjs` recorded from the original (Pi 1.3.0's `pi-tui` for colours and widths; re-running `drive.mjs` under
  Node 24.22.1 reproduces the committed file byte for byte):
  `TestParseMatchesOriginal` (5,034 texts), `TestGrowMatchesOriginal` (2,338 cases, four themes' colours, ten progress
  values, 121 of them Thai, Lao, Khmer and Myanmar), `TestSessionsMatchOriginal` (11 recorded sessions of draws, clicks,
  letters and themes) and `TestGuideIsTheOriginals`.
- `adapter_test.go` drives the real SDK through a fake PiG host (`fakehost_test.go`) over the wire: the events,
  shortcuts and transformer it registers; the link claim and its release; nothing asked outside a terminal session;
  the attach redraw; a click opens a stretch and the transcript is drawn again (`invalidate` then `requestRender`); an
  unknown address changes nothing; the guide and the read note; the letter shortcut; a session replacement claims the
  scheme again.
- `survivors_test.go` and `adapter_survivors_test.go` hold the tests the mutation run asked for.

Mutations: `mutations.json` holds 56 mutants (letters and their number, the open/close state machine, colours and fade,
the SGR underline and reverse, link addresses, code spans and fences, keys and shortcuts, the redraw worker, the guide
and the read note). `mutate.py` runs each against the extension's tests in a sibling copy (`pigeq mutate` copies the
module into a scratch directory, which loses the `go.work` that reaches `components/pitui`): **56 of 56 killed**. The
first run killed 42 of 57; 13 survivors got tests, one mutant did not build (repaired) and one is equivalent
(`mutations-equivalent.json`: `isSpaceAt` is never asked for `len(run)`).

Real terminal, tmux, Pi 1.3.0 with the original against pig with the port, a scripted OpenAI-compatible model
(`tmux/mockllm.py`), 100×32, `compare.py` drops the footer, the startup warning and the spinner frame:

| Scenario | What it does | Pi and PiG |
|---|---|---|
| `click` | open, open the nested stretch, close it, close the first | 5 of 5 screens equal |
| `keyboard` | `alt+o`, a letter, `alt+o` and Escape, `alt+c`, a letter, `alt+c` with nothing open | 8 of 8 equal |
| `streaming` | the reply arrives 7 characters at a time; click after it | 4 of 4 equal |
| `compaction` | click, two plain turns, `/compact`, a new reply, click, `alt+o` | 5 of 5 equal |
| `resume` | `/new`, a reply, `/resume` the first session, click, a new reply, click | 5 of 5 equal |

`resume` and `compaction` are the session replacements of a real pig: after `/new`, `/resume` and compaction the
extension's context still draws and clicks repaint.

Performance against the original on the same input (`perf/`): parsing a 3.4 KB reply, 202 to 212 µs (Go) against
311 µs (Node 24.22.1); growing one long form at ten progress values, 120 to 129 µs against 279 µs. See
[`RESEARCH.md`](RESEARCH.md).

## Built into pig-with-batteries

`piglets/pig-with-batteries` selects the extension (with `pitui`, the library module the segmenter lives in). A Piglet
Binary built from the manifest runs the `click` scenario with the same screens as the Package, apart from the model-guard
hint another battery prints. Unlike the other batteries this one changes how replies read from the first prompt (it adds
the guide to the system prompt), so it is the owner's call whether it belongs in the composition.
