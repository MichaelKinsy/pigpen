# a2a: port record

**Kind of port (Skill, "What kind of port is this?"): 3, new code with no original.** a2a is an *original adapter* on the upstream
Go SDK [a2a-go](https://github.com/a2aproject/a2a-go) v2.6.0 (commit `ebf17c56ef7e63c72883a45454a538bbc0df66b8`, Apache-2.0). There
is no TypeScript or Pi original to twin, so there is **no Pi oracle and no equivalence claim**. The golden traces in `golden/` are
**self-recorded** regression baselines (lane `pig-go-self`): the port was recorded from itself and reviewed by hand, and `pigeq check`
labels them that way. What replaces the oracle for protocol facts is a2a-go's own contract plus an independent A2A peer (below).

## Gap check against the SDK surface

Everything the extension uses is fully provided by the 0.3.0 Go SDK: `sdk.New`, `RegisterTool`, `RegisterCommand`, `RegisterFlag`,
`OnEvent("session_start"|"session_shutdown")`, `Context.Notify`, `sdk.NewToolError`. No `PARTIAL` or `MISSING` (`pigeq gaps --go`).
Fused-extension rule found in `pig docs show extensions`: a fused extension shares PiG's process, so a2a discards the HTTP server's and
a2a-go's logs (`ErrorLog` and slog to `io.Discard`, `RecentLogs` ring instead) rather than writing to PiG's terminal.

## Capabilities (tracked follow-ups, `gaps_test.go`, `capability.go`)

Owner decision 2026-10-20: optional functionality is not limited prematurely. Each capability below is a **tracked follow-up, not "won't do"**. Until one is implemented it stays advertised false on the Agent Card, refused with the exact sentence `@pi-in-go/pigpen-a2a does not support <feature> yet.` and the specification's error code (C32), and is an explicit opt-in seam:

- `capability.go` holds a small registry. A `Capability` (key, `Advertise(card)`, `Mount(mux, handler)`) registers itself; the server consults the registry to advertise (`card()`), to serve (`Mount`) and, through the guard, to stop refusing what is switched on (push methods, extended card, A2A 0.3).
- `a2a.json` has `"capabilities": {"grpc": false, "rest": false, "pushNotifications": false, "protocol03": false, "extendedAgentCard": false, "urlFileParts": false, "oauth2": false, "mtls": false, "signedCards": false}`; every key defaults to false, the object rejects unknown keys and non-booleans like the rest of the file, and switching one on while no implementation is registered is an error when the configuration is loaded (and from `NewServer`) with exactly the refusal sentence, never at call time. Tests: `TestCapabilitiesAreOffByDefault`, `TestEnablingACapabilityWithoutAnImplementationFailsAtConfigLoad`, `TestCapabilitiesObjectRejectsUnknownKeysAndNonBooleans`, `TestEveryCapabilityKeyHasExactlyOneSpecAndOneFlag`, `TestARegisteredCapabilityIsAdvertisedMountedAndNotRefused`, `TestProtocol03IsAcceptedOnlyWhenItsCapabilityIsOn`; mutants `capability-*`, `card-advertises-push-by-default`, `guard-*`, `protocol03-flag-ignored`.

## Host findings (for the porter and PiG)

- **a2a-go v2.6.0 defect 2 (port/a2a-1):** `SendMessage`/`SendStreamingMessage` with a `taskId` that is another principal's *live* task answers "task execution is already in progress" instead of "task not found", so any authenticated caller could tell that an id is a running task. The port's `guard` checks ownership before the handler runs (`TestSecondPrincipalIsRefusedOnEveryTaskRPC`, mutant `followup-ownership-unchecked`). Found by writing the second-principal test for every RPC.
- A streaming method (`SendStreamingMessage`, `SubscribeToTask`) answers its errors as server-sent events (`id:` and `data:` lines), not a JSON body, even when the error is the first event; a raw-HTTP test reads the `data:` line.
- One listener per `stateDir` (README, Persistence): the store does not lock its directory, so a second listener started on the same one would take the first one's running tasks for interrupted ones and mark them failed. Not guarded in code: a lock file would need per-platform locking for a configuration that already shares session files unsafely.
- a2a-go's `taskstore` validator and deep copy are unexported, so the file store keeps each task as the JSON that is also its file content and copies by decoding; the in-memory store's metadata validation is not repeated (JSON refuses what it cannot encode).
- The fake-host template's `Command` sent the wrong request shape (fixed in the porter branch); a tool's own argument check runs, since the host does not validate schemas in the fake.
- A stale `go.mod` passes workspace tests but fails PiG's packed build (missing `go.sum` entries): always `go mod tidy` with the full source, then build a Binary.
- kagent's ADK server hard-codes its readiness port `:8081`; kagent's client repeats the `A2A-Version` header (`1.0, 1.0`); a2a-go's in-memory task store lists tasks only for an authenticated user.
- **a2a-go v2.6.0 defect (reported here, not fixed upstream):** `SubscribeToTask` on a *live* task attaches to the task's event queue without an ownership check
  (`a2asrv/handler.go`, `execManager.Resubscribe` before `taskStore.Get`), so any authenticated caller who knows a task id can read another tenant's live stream. `GetTask`,
  `CancelTask` and `ListTasks` are masked. The port owns the task store and checks ownership in its call interceptor (`guard`); `TestSubscribeToALiveTaskDeliversTheRest`
  and mutant `subscribe-ownership-unchecked` pin it. Found only by writing the roadmap's "stream resubscription" item with a second principal.
- a2a-go's client ends the event stream with an error on cancel, so a "cancel after clean end" branch would be dead code (removed).
- `go.work` written by `pigeq` uses `go 1.26`, which is below `go 1.26.0`; needed a local fix.
- PiG 0.3.0's `read`, `grep`, `find` and `ls` resolve absolute paths and `~` outside the working directory
  (`internal/codingagent/tools/path_utils.go` `resolveToCwd`), so a tool allowlist is not a file-access boundary. The worker
  therefore defaults to `--no-tools`; a PiG option that confines file tools to the working directory would let a served
  worker have read tools safely.
