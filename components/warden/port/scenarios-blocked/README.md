Scenarios that cannot be recorded yet, with the reason.

- `git-*.json` (real git in a workspace repository): `pigeq run` fails its host check, because the host's own `git rev-parse --is-inside-work-tree` and the first `message_end` arrive in a different order under Pi and under PiG's Node runtime (host check: pig-ts differs from pi-ts at event 3). That is a host ordering difference, not normalized away here. The behaviour is covered by `gitstate_test.go` with real git.
- Escalation configs need a judge; they are covered by the fake-judge tests. Path-rule and arming scenarios moved to `port/scenarios` once pigeq had `homeFiles`.
- `notify-held-call-runs-the-configured-command.json` (a notify command spawned by a held call): the shim's `exec` event and the host's `tool_execution_end` for the held call arrive within a millisecond or two of each other, in an order that changes from run to run; the original under PiG's Node runtime differs from the original under Pi at event 8 in one of two consecutive runs (host check: pig-ts differs from pi-ts). That is a host ordering race, not something to normalise away. The behaviour is covered by `TestDesktopNotificationsForAHoldAConfirmAndARunawayStop` (layer 1, with the real spawn path covered by `TestNotifierCommandsSpawnInTheCall`).
